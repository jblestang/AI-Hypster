# 1. Preparative Boot & Verification Procedures (AGD_PRE.1)

## 1.1 Secure Binary Verification & Checksum Audit
Before deploying the Hypster executable onto target hardware, system administrators must verify the cryptographic SHA-256 hash of the bootable UEFI image:

```bash
sha256sum /boot/efi/EFI/BOOT/BOOTX64.EFI
```

The computed digest must match the release hash generated by the certified build pipeline.

## 1.2 Static Partition Configuration Binary (`VMIT`) Validation
1. **Schema Integrity Check**: System administrators author partition definitions in `config.rs`.
2. **Pre-Boot Validation**: Executing `StaticHypervisorConfig::validate()` verifies:
   - Partition RAM ranges are strictly non-overlapping.
   - Core pinning maps 1-to-1 (`vCPU 0 -> Core 0`, `vCPU 1 -> Core 1`).
   - PCI BAR MMIO regions are assigned to authorized System Partitions only.

# 2. Operational User Guidance (AGD_OPE.1)

## 2.1 Partition Developer Guidelines
1. **No-Hypercall Constraint**: In steady-state operation, guest partition code must not issue `vmcall` instructions. Inter-partition messaging is conducted strictly via lock-free atomic SPSC ring buffers mapped at `0x140413000`.
2. **PCI MMIO Passthrough**: System Partition driver domains accessing physical PCI BAR MMIO must execute direct reads and writes against assigned GPA regions (`0x20000000` / `0xC1080000`).

## 2.2 System Administrator Maintenance Procedures
1. **Partition Health Monitoring**: Administrators can inspect serial UART diagnostic logs (`115200 8N1` on port `0x3F8`) to monitor partition health recovery events (`GLOBAL_HEALTH_MONITOR`).
2. **Unrecoverable Fault Handling**: If a partition exceeds its maximum reset quota (e.g. 5 consecutive triple faults), the TSF maintains the failed partition in isolated reset state while peer partitions continue executing normally.
